## 메뉴별 기능

### 수입 (`/dashboard/household/income`)
- 수입 거래 등록/수정/삭제: 날짜·항목(카테고리)·입금처·금액·입금계좌
- 목록(월 필터·검색·정렬), 입금처별/항목별 합계
- 상단 StatCard: 이번 달 수입 · 전월 대비 · 올해 누적

### 지출 (`/dashboard/household/expenses`)
- **일시불 지출**: 날짜·지불방식·은행·카테고리·내역·금액·용돈사용(인물)·비고
- **할부 지출**: 총금액·회차 입력 → 매월 자동 분할 반영, 진행 회차/잔액 표시
- 목록(월·카테고리·지불방식 필터), 카테고리별 합계
- 상단 StatCard: 이번 달 지출 · 전월 대비 · 올해 누적

### 현금관리 (`/dashboard/household/cash`)
- 계좌 목록 + **현재 잔액 자동 계산**(거래 반영) — 본인·배우자·가족 계좌 포함
- **통장 이동**(이체) 등록: 출금계좌 → 입금계좌
- 계좌별 거래내역, 총 보유자금
- 계좌번호 표시(설정 화면은 가려서, 현금흐름 계좌 표는 저장된 값 그대로)
- **상단 요약: "이번 주/이번 달 나갈 돈 vs 현금 보유" + 부족 경고**(현금흐름 예측 연동)

### 대출관리 (`/dashboard/household/loans`)
- 대출 목록: 잔액·이자율·월납입금·만기일·다음 상환일
- 상환 거래 연결 → 잔액 자동 감소
- 상단 StatCard: 총 대출잔액 · 월 상환액 합계 · 평균 이자율
- (2차) 상환 스케줄/알림

### 통계 (`/dashboard/household/stats`)
- **★ 현금흐름 예측 / 자금 스케줄 (핵심):** 주간/월간 단위로 나갈 돈(자동이체·카드대금·대출·할부) 합산 → 현금 보유 대조 → 부족일 경고 (아래 전용 섹션 참고)
- 다가오는 지급 캘린더/리스트
- 월별 수입·지출·수지 추이(막대/선 그래프, recharts)
- 카테고리별 지출 비중(원그래프)
- 지불방식별·인물별 사용 현황
- 연간 요약(엑셀 `연간요약`·`월고정비현황` 대응)

## 자동 계산 규칙 (엑셀 수식의 대체)

### R1. 계좌 잔액
```
계좌.현잔액 = 계좌.기초잔액
            + Σ(income.금액  where 입금계좌 = 계좌)
            + Σ(transfer.금액 where 입금계좌 = 계좌)
            − Σ(transfer.금액 where 출금계좌 = 계좌)
            − Σ(payment.금액  where 출금계좌 = 계좌)
            − Σ(expense.금액  where 결제수단의 연결계좌 = 계좌 그리고 현금/체크)
```
> **[확정]** 신용카드 일시불·할부는 결제 시점이 아니라 **카드대금 납부(payment) 시점**에 계좌에서 빠진다(엑셀과 동일).

### R2. 월 현황(블록 01) 집계
- 수입 합계 = Σ income(해당 월)
- 카테고리별 지출 = Σ expense + Σ 할부 월금액(해당 월 회차) — 카테고리별 group by
- 지불방식별 지출 = 위를 payment_method로 group by
- 잔액(월) = 수입 − (지출 + 카드/대출 납부)

### R3. 할부 월 분할
```
월금액 = 총금액 / 총회차   (반올림 오차는 마지막 회차에서 보정)
현재회차 = (이번 달 − 시작월) + 시작회차
남은잔액 = 총금액 − (지난 회차 수 × 월금액)
```
- 해당 월이 `시작월 ≤ 이번달 < 시작월+총회차` 범위면 그 달 지출에 월금액 반영.

### R4. 대출 잔액·상환
```
대출.현재잔액 = 대출금액 − Σ(연결된 payment 거래의 원금분)
```
- 단순 모델: 월납입금 전액을 잔액에서 차감(원금/이자 분해는 2차).
- 다음 상환일 = 최근 상환일 + 1개월(또는 약정일).

### R5. 용돈/인물별 집계
- person이 지정된 expense를 인물별 group by → "용돈/외식비 사용 현황".

### R6. 부호 규칙
- 저장은 **양수 + 유형(type)** 으로(엑셀의 음수 혼용 제거). 표시·집계 시 유형에 따라 부호 적용.
- **[확정]** 엑셀 수입 칸에 음수로 적힌 항목(증권 매수 등)은 수입이 아니라 **증권계좌로의 이체(`transfer`)로 재분류**한다. import 시 자동 변환.

## 자동 수집 → 검토 → 확정 파이프라인 ★ [확정 방향]

수입·지출의 **약 95%를 자동 입력**하고, **한 번 점검한 뒤 DB에 저장**하는 흐름. (핵심 요구 사항)

```
[자동 수집] → [수집함(pending)] → [자동 분류] → [사람이 한 번 점검·수정] → [확정] → [hh_transaction] → 잔액·통계 반영
   95%                              규칙+AI         일괄/개별 확인         5% 수동입력은 여기로 바로
```

### 단계별 규칙
1. **수집(ingest):** 외부 소스에서 거래 후보를 받아 `수집함`에 적재(상태 `pending`). 원문·출처 보관.
2. **자동 분류(auto-categorize):**
   - 1차 규칙: 가맹점명/입금처 → 카테고리·계좌·결제수단 매핑 사전(학습된 매핑 테이블).
   - 2차 AI(보조): 규칙 미스 건만 Anthropic SDK로 카테고리 추정(신뢰도 표기). 원작 템플릿의 `deposits/ai-match` 패턴을 본뜬다는 계획이었다(그 코드는 이 저장소에 없다).
3. **중복 제거:** (날짜+금액+가맹점+출처) 키로 기존 거래/수집함과 대조해 `duplicate` 표시.
4. **점검(review):** 검토 화면에서 목록 확인 → 카테고리/계좌만 수정 → 체크 후 **일괄 확정**. 한 건씩 확정도 가능.
5. **확정(confirm):** `confirmed`로 전환되며 `hh_transaction` 생성. 이때부터 잔액(R1)·집계(R2)에 반영.
6. **학습:** 사용자가 고친 (가맹점→카테고리) 결과를 매핑 사전에 반영해 다음부터 정확도 향상.
7. **수동 5%:** 현금 등 자동수집 안 되는 건은 검토 화면에서 직접 추가(바로 confirmed 가능).

### 자동화 전(AS-IS) 방식
- 신용카드: 카드사 사이트·앱에서 내역 확인 → 수기 입력.
- 은행/체크카드: 은행 앱에서 내역 확인 → 수기 입력.
- → 수집 자체가 수동이라 번거로움. 이 **수집을 자동화**하는 것이 목표.

### 수집 소스 (제안)
한국에서는 마이데이터 API(인가 필요)·카드사 자동 로그인 스크래핑(2FA·약관·차단 위험)이 개인앱엔 부적합.
**현실적·안정적 대안 2가지를 병행**한다:

| # | 방법 | 작동 | 커버 | 비고 |
|---|------|------|------|------|
| ① | **결제 문자(SMS) 자동 전달 → 파싱** | 카드 결제 알림 문자를 폰이 webhook으로 전송 → 수집함 적재 | 신용·체크카드 결제 실시간 | 안드로이드 쉬움 / 아이폰 제약. 이체·현금 미포착 |
| ② | **명세서·거래내역 파일 업로드 → 파싱** | 은행 앱·카드사의 CSV·엑셀 다운로드 → 업로드 | 은행·체크·누락분 정산 | 월 1~2회. 누락/중복 없이 검증 |

- **운영:** ①로 평소 자동 수집 → ②로 월말 정산·누락 보정.
- **[확정] 폰 OS = 안드로이드** → ① 결제문자 자동전달이 주력. (MacroDroid/Tasker 등으로 결제 문자 → webhook 전송)
- **[확정] 다인 계좌:** 본인(김하늘) + **배우자(이바다)** + 가족 계좌·카드를 모두 다룬다. 인물(Person) + 계좌/결제수단 명의로 구분. 배우자 계좌도 수집·잔액·집계 대상.
- 파서는 카드사/은행별 문자·파일 포맷이 달라 **포맷별 어댑터**로 구현(02의 `수집함` 원문 필드에 출처·원문 보관).

> 다음: 02의 `수집함` 필드(원문 포맷)와 **카드사/은행별 파서 어댑터 목록**(삼성·현대·국민·하나 카드, 토스/농협/국민/우리/하나 은행 등)을 확정한다.

### 지역화폐 규칙 (예시)

지역화폐 규칙은 가상 이름 '한빛페이' 기준의 예시다. 실제 지역화폐 알림은 이름이 달라 그대로는 맞지 않는다.

| 규칙 | 하는 일 | 있는 곳 |
|---|---|---|
| 충전 이체 | 상대처에 '지역화폐'나 지역화폐 운영사 이름이 들어 있으면 이체로 보고, 출금계좌 주인의 '한빛페이' 지갑을 도착 계좌로 고른다 | `src/lib/household/defaults.ts` 의 `DEFAULT_TRANSFER_RULES` |
| 충전 인센티브 | 이름에 '한빛페이'가 든 계좌로 충전하면 충전액의 10%를 수입으로 함께 기록한다 | `src/lib/household/defaults.ts` 의 `CHARGE_INCENTIVE_RULES` |
| 지갑 결제 | 결제 알림의 '한빛페이' 표기와 총 보유 잔액으로 어느 지갑에서 나갔는지 고른다 | `src/lib/household/sms.ts`, `sms-ingest.ts` |

- 지갑은 **계좌 1개 + 결제수단 1개**로 등록한다. 결제수단은 종류 '현금'에 지갑 계좌를 연결한다. 이름은 `한빛페이(김하늘)`처럼 `이름(소유자)` 꼴로 짓는다.
- 더미 데이터(`npm run seed:demo`)에는 지갑 계좌와 결제수단 `한빛페이(김하늘)`이 들어 있다.
- 자기 지역화폐에 쓰려면 Claude Code 에 "지역화폐 이름을 ○○페이로 바꿔줘"라고 시킨다. 규칙·알림 해석·계좌 이름을 함께 바꿔야 한다.

## 현금흐름 예측 / 자금 스케줄 ★★ [핵심 요구 — 통계의 중심]

> 핵심 목적: **앞으로 나갈 돈을 미리 합산해 현금 보유와 대조 → 지급일에 돈이 모자라지 않게(신용 문제 방지) 미리 경고하고 자금을 옮긴다.**
> "지나간 통계"가 아니라 **앞날을 보는 자금 스케줄러**.

### 무엇을 예측하나 (예정 지출 = 나갈 돈)
1. **자동이체/정기지출**(ScheduledPayment): 보험·통신·관리비·적금·구독 등 — 납부일·금액
2. **대출 월납입금**(Loan): 약정일·월납입금
3. **할부 월금액**(Installment): 진행 중 회차의 이번/다음 달 금액
4. **카드대금 추정**: 아직 결제 안 된 카드지출 누적 → 카드별 결제일·예상 청구액
5. (선택) **예상 수입**: 급여 등 정기 수입(ScheduledPayment의 income판)

### 어떻게 보여주나
- **주간/월간 타임라인**: 기간별로 `예정 지출 합계`, `예상 수입`, 누적 `예상 잔액`.
- **현금 보유 대조**: 각 시점의 예상 잔액 = 현재 현금 보유(계좌 잔액 R1) + 예상수입 − 예정지출(누적).
- **부족 경고**: 어떤 지급일에 예상 잔액이 **버퍼(설정값) 미만**이면 경고 표시 + 부족액·필요 이체 제안.
- **자금 조절 제안**: "X일 카드대금 OOO원 전, 토스뱅크 잔액 부족 → 우리은행에서 △△ 이체" 식 가이드.
- **달력/리스트 뷰**: 다가오는 자동이체·카드대금·대출 상환을 한 화면에.

### 계산 규칙
```
기간별 예상잔액(t) = 현재 총 현금보유
                   + Σ 예상수입(≤t)
                   − Σ 예정지출(≤t)            # 자동이체 + 대출 + 할부 + 추정 카드대금
경고(t) = 예상잔액(t) < 안전버퍼
```
- 카드대금 추정: `confirmed`/`pending` 카드 지출 중 미결제분을 카드별 결제주기에 맞춰 다음 결제일에 합산.
- 계좌별로도 동일 계산(특정 출금계좌가 마이너스 나는지) → 어느 통장에서 부족한지 콕 집어줌.

### 화면 배치
- **통계** 메뉴: 현금흐름 예측 타임라인(주간/월간) + 다가오는 지급 캘린더 + 과거 추이/비중 그래프.
- **현금관리** 메뉴: 상단에 "이번 주/이번 달 나갈 돈 vs 현금 보유" 요약 위젯 + 부족 경고.

## 데이터 이관(import) 규칙

- 월별 시트를 블록 헤더로 탐지 → 블록별로 거래 유형 부여해 Transaction으로 적재.
- 마스터(계좌·카테고리·결제수단·대출·인물)는 시트 전체를 스캔해 **유니크 값 추출 후 사전 생성**, 거래는 이름으로 FK 매칭.
- 시기에 따라 열 수가 다른 시트는 헤더 라벨 기준으로 매핑(고정 인덱스 사용 금지).
- 자격증명·민감 칸은 **import 제외**.
- import 후 월별 합계를 엑셀 현황(01)과 대조하는 **검증 리포트**를 만든다.

## 보안·프라이버시

- 은행 로그인 ID/비밀번호: **이전하지 않음**(스키마에 필드 없음).
- 계좌번호: 저장한다. 설정 화면은 가려서 보여 주고, 현금흐름 계좌 표는 저장된 값을 그대로 보여 준다 — 전체 번호 대신 가린 표기(예: `110-11-0***-111`)로 입력하는 편이 안전하다.
- 가계부는 개인 데이터이므로 Supabase RLS로 **본인 데이터만** 접근하도록 정책 적용(05에서 설계).
